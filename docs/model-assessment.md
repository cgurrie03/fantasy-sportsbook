# Weekly assessment and controlled configuration

Implemented 9 October 2026. This is a fixed application pipeline, not an LLM training/deployment task. Accuracy is an estimate, not a guarantee. Ticket popularity, stake, profit and user losses never enter its objective.

## Archives and evaluation population

`model_forecast_runs` captures every successful generation in Matchups, Player Points, Weekly Specials and Season Futures before the returned quotes can be published. An archive failure aborts generation and retains existing lines. Sources include scoring/roster rules, fetched timestamps, provider payloads, history, known lineups, projection inputs, simulation seed, full special distributions and model/config identity. Only rostered projections are retained; unrostered players cannot affect these generated forecasts. Provider observation times that are unavailable remain explicitly unknown. Cached sources retain their original fetched timestamp; reading the cache is not a fresh upstream observation.

`forecast_snapshots` retains the actual published board, including price/boost terms. Run IDs in quote metadata associate published quotes with their original inputs. Existing published/install-time snapshots are never relabelled as complete as-of source archives. Opening in this assessment means the first generated as-of run per family; the existing opening-published report remains a distinct view. Final pregame means the latest as-of run before the first confirmed NFL kickoff of the week. This conservative common cutoff avoids including any live information in pregame metrics. All runs remain available in the archive; repeated quote refreshes do not add independent evaluation samples. Both selected horizons are reported separately.

`live_forecast_runs` and `live_model_reviews` retain the existing experimental actual-starter remaining-points model, blocked-run reasons and selected progress-quartile horizons. Live remains shadow-only, with betting acceptance disabled. The broader review includes its latest confirmed review. Live failure is isolated from the broader review, and neither review path invokes settlement, replenishment, recap, publication or rollover.

`model_outcome_revisions` stores append-only confirmed outcomes, raw score evidence, starters, played/inactive status, source settings and final season results. Independent league-scored player stats must agree with starter scores and summed roster points within 0.11 points; manual overrides and incomplete/conflicting results defer assessment for review. Completed NFL week state and matching ESPN season/week with every game final are required. Open weekly tickets defer assessment until settlement reconciliation. Futures tickets do not block a completed-week review.

`model_weekly_reviews` stores the report, input digest and candidate comparison immutably. Same inputs/state produce the same review ID. Corrections append a new outcome/review; latest revisions supersede old revisions for current analysis without deleting them. Old reports contain their own recorded values and remain readable after configuration changes. Accepted-ticket snapshots and published beat-projection benchmarks remain untouched.

## Metrics and distinctions

The population is generated predictions, including unbet/locked markets, rather than ticket-selected predictions. Families and horizons have separate generated, published, scored, push, pending and missing-probability counts. Calibration bands are descriptive proportions, not independent-trial confidence intervals.

- Score error is forecast minus actual. Report MAE, RMSE, bias, mean/median, percentiles, spread and 80% interval coverage. Keep genuine extreme games.
- Team-market error includes managerial lineup differences. Best-lineup conditional error compares the archived selected players' forecast with those same players' realized points. Actual-starter error sums only final starters whose forecasts existed in the archived roster pool. Forecast and realized selection gaps are separate; absent as-of starters are excluded rather than reconstructed from a later roster.
- Player diagnostics separate position, horizon and participation. Original capped historical/provider blend remains unchanged: 15% shrinkage with a ±15% provider-projection adjustment cap; no extra questionable-player injury discount is added.
- Player fair probabilities/intervals are new **shadow diagnostics**, not a recalibrated production player-price model. A normal distribution uses the original expected score and historical variance shrunk toward `(provider projection × 0.5)^2`, with weight `n/(n+8)` and SD floor 2. Posted fixed -110 prices are unchanged. Availability mixtures and position-specific uncertainty require validation.
- Moneyline retains its original capped logistic fair probability. Spread/team/match totals archive normal-distribution diagnostics independently of displayed fixed-margin prices, rounded lines and boosts. Binary Brier/log loss uses fair probability, clipping only log loss at 1e-6. Push/inactive outcomes are explicit and excluded from binary win/loss scores. Margin, total, team and player point errors are also reported.
- Highest/lowest score uses the full categorical field, categorical Brier/log loss and omitted top-six probability mass. Tied winners are reported separately. Exact-count distributions include the zero count even where it is not offered; At Least choices are scored from tail probabilities rather than added as exclusive categories. Counts report expected count, error, histogram and interval coverage. Average and maximum scores use the joint simulation samples, not the maximum projected mean.
- Futures retain probability/win-distribution trajectories. Only confirmed qualification, champion, regular-season last place and regular-season win outcomes enter final scores. Regular-season provider `last_report` must confirm the last regular week. Current standings are never substituted. Opening forecasts are selected once per origin week/event for descriptive final scoring; many origin weeks predict the same season event and are correlated, not independent samples. Pick ownership remains separate from the last-place event.

## Candidate and promotion policy

The immutable initial configuration is the existing `weekly-lineup-v3` team baseline, with score and SD scales both 1. The only tunable fields are team `score_scale` and `variance_scale`; player, live and futures price algorithms remain frozen. There is one predeclared shrinkage candidate, no arbitrary source edits and no search for a profitable bookmaker configuration. Recency/history weighting is not added because the existing player adjustment already uses that signal.

Minimum evidence: 8 training weeks, 12 chronological validation weeks, 4 untouched recent holdout weeks; at least 120 actual-starter validation observations and 40 holdout observations. Only the same league is pooled across seasons, with matching scoring settings and roster positions. No cross-league pooling is implemented. Latest corrected results whose review was recorded after a historical prediction time cannot train that earlier fold; conservative exclusion is used instead of reconstructing what was known.

The candidate shrinks residual score/variance estimates with `weeks/(weeks+24)`. Per promotion, each parameter changes at most 2% relative to active values, with absolute scales bounded to [0.9, 1.1]. These are conservative operational choices, not statistically proven power thresholds. A seven-day promotion cooldown applies.

Validation refits using only earlier available completed weeks. The final holdout candidate is frozen using the training partition; holdout outcomes never fit its parameters. Paired week-block percentile bootstrap uses 6,000 draws, seed 74291, and 99% intervals. Require positive lower confidence bound for MAE gain versus active, nonnegative lower bound versus the frozen initial baseline, and at least 2% practical MAE gain in both validation and holdout.

Replay uses original archived inputs and original quote lines. Full special distributions are reseeded reproducibly, including frozen original beat-projection count targets. Affected-family Brier regression cannot exceed 0.01 and log-loss regression cannot exceed 0.02 versus the better of active/frozen baseline for any selected week/horizon. No team's score error may regress by more than max(1 point, 5%); interval coverage deviation from 80% cannot worsen by more than 5 percentage points. Missing source replay, missing market families and unresolved affected outcomes fail the safety gates. These conservative per-week tolerances supplement the primary block-confidence gate; they are not proofs of calibration or causal improvement.

`control_model` only permits the server worker to promote a fresh passing review. Database-side checks enforce sample/confidence gates, bounds, current-version comparison, cooldown, league scope and pause state. A promotion appends a config version and audit event and atomically changes the active pointer. Failure/insufficient evidence records a hold and retains the active model. Admins can pause/resume or restore the previous version; they cannot override a failed review to promote. Rollback pauses improvement.

After promotion, production forecasts retain original inputs so comparisons can be made against the frozen baseline. Missing required family coverage or invalid monitoring data triggers automatic rollback. For score drift, require four completed week blocks for the active version and a 99% lower bound showing >2 points MAE degradation versus baseline before rollback. Rollback restores the parent (or initial baseline), never changes accepted tickets, and records the cause. Database/source outages that prevent a review cannot establish statistical drift: archive failure retains existing prices and the review job retries through the existing queue.

## Operations, review and rollback

Migration 032 adds league-scoped admin-read RLS and append-only tables/RPCs. Direct authenticated/service-role table mutation is revoked; authorized security-definer functions provide narrowly scoped writes. New leagues receive an initial frozen config but remain subject to existing default-off launch controls. Existing daily, lower-priority `model_review` jobs now discover both pregame and live archives. Settlement/replenishment/mail priorities and leases remain intact. Daily next-week reviews append corrections. Assessment failure cannot execute or undo wallet/ticket changes.

Admin Reports → Forecasts & Model Accuracy → Model Accuracy & Special Trends includes the compact review, separate residual/reliability/coverage charts, calibration/coverage details, special/future diagnostics, candidate gates, version history, pause and rollback. Empty state waits for confirmed results. Only local fixtures demonstrate the preview; no production accuracy claim is made from them.

For application rollback, restore the prior Vercel application while retaining additive migration 032, accepted-ticket rules and N+ settlement support. For configuration rollback, use the admin control; do not update/delete version records. Do not roll back to a pre-N+ settlement implementation after N+ tickets exist. Run hosted concurrency and worker-capacity tests before another league; local PGlite tests do not prove contention safety.

Method references: [chronological validation](https://otexts.com/fpp3/tscv.html), [paired bootstrap and percentile intervals](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html). The implementation resamples whole league-week blocks to preserve within-week dependence. Serial dependence across weeks and repeated weekly gate checks can still weaken interval interpretation; the 99% threshold does not guarantee absence of false promotions.

## Verification and current limitations

`npm run test:model` verifies independent known numeric/probability fixtures, lineup decomposition, cutoff/horizon deduplication, incomplete/push/inactive/pending-futures treatment, seeded reproducibility, future-result leakage rejection, bounded promotion/hold/pause, append-only corrections, rerun idempotency, rollback and old-report preservation. Existing live, weekly, futures, line, refresh, starters, reporting and isolation suites cover unchanged accepted snapshots, settlement, refunds, replenishment, leases, tenant isolation and publication. Build includes compiled function-runtime import/auth checks.

Not yet established: calibrated joint NFL correlations, provider heartbeat freshness, validated player availability mixtures, statistically powerful production promotion evidence, hosted simultaneous transactions, multi-league worker capacity and physical-device review. Strict source/score reconciliation can defer an entire review; the queue records the reason and retries. Missing legacy inputs are never backfilled with today's rosters/projections and relabelled as historical evidence. This release starts prospective complete archive collection.
