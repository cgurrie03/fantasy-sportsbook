# AUD-10 / AUD-11 / AUD-14 / AUD-16 Delivery

Development deployment: `dpl_7F1ZG1xgNALZ7o3SGNdX7gK54bWo`, November 18, 2026. Production is untouched.

Assigned to `dev.sportsbook.coopergurrie.com` after final hosted verification. Temporary users, sessions, identities, grants and links removed; baseline restored to 1 Auth user, 3 leagues, 14 memberships, 0 temporary co-manager links, 91 tickets and 261 legs. No real betting or credit transactions were performed.

## Changes

- **AUD-16:** Reject malformed JSON, oversized bodies, invalid ticket identifiers/types, unsupported/duplicate query parameters and malformed revision/history cursors before database reads. Bound page sizes and search terms. Client errors return 400/413 rather than a generic outage; upstream failures remain service errors. Valid ticket placement and lightweight refresh contracts are preserved.
- **AUD-14:** Enforce Content Security Policy, frame-ancestors none, X-Frame-Options DENY, nosniff, a referrer policy and restricted camera/microphone/location permissions. Script execution is limited to same-origin assets and the Vercel toolbar origin. Existing inline styles remain permitted; inline scripts/eval are not enabled. Supabase HTTP/WebSocket connections, first-party fonts, HTTPS avatars, notification workers and sandboxed email previews remain supported.
- **AUD-11:** Each award has an explicit Allow All checkbox. Defaults are unchecked with the existing numeric default cap; previously saved unlimited settings remain unlimited. Checking it disables the cap input and stores the established zero/unlimited value. Unchecking restores the prior cap or its default. Confirmation/save and existing co-manager grouping rules remain intact.
- **AUD-10:** Initial book responses include bounded recent activity rather than every ticket and wallet entry. Fetch at most 10 league tickets plus 8 caller-owned recent tickets for personal notifications, deduplicated. Ticket pages use 25-row keyset pagination and server-side status/week/participant/search/sort across the entire archive. All four sort modes have stable tie breakers. Balance history loads only in its view, in pages. ATS archive data loads separately. League/owner analytics retrieve complete history in cancellable pages only when those views are opened, preserving complete totals.
- Historical unattributed tickets remain filterable by historical team, without becoming a replacement/co-manager's personal history. Personal notifications now use immutable wallet ownership rather than a shared team's manager name.

## Verification

- Production TypeScript/build and request/history, account isolation, source access, fantasy reward and weekly reward regression suites passed.
- Real Development SQL cursor traversal covered all current tickets in each of four sort orders without duplication or omission. A second rolled-back test added 1,005 fixture tickets and traversed the resulting history beyond 1,000 without truncation. No fixture tickets persisted.
- New co-managers receive no inherited personal tickets or ledger. Unrelated users and unverified users are denied; checks cover direct RPCs as well as the API.
- Desktop/mobile production-bundle tests: page loading, Load More, search for an item beyond row 1,000, personal scope, reward checkbox defaults/disable/restore/save, balance history expansion/pagination, no page errors or horizontal overflow.
- Hosted checks: security headers, deliberate inline script rejection and external framing rejection; malformed JSON/parameters; unrelated-user denial; complete cursor traversal; personal-history isolation; archive and unchanged-board requests; ticket/reward UI; sandboxed owner email preview.
- Uncompressed full-response observations: approximately 2.19 MB before and 1.87 MB after, with 1,495 quotes in both observations. Final samples span a background board revision, so this is an observed reduction rather than a controlled load benchmark. The unchanged-board response was 3,114 bytes in the test (offers included).

## Storage And Performance

Two bounded read RPCs and a participant-filter follow-up migration were added. No new data tables, continuous jobs or indexes were added. Pagination uses existing ticket/leg/wallet indexes; history bodies are serialized for the requested page only. Searches and summary counts still require scoped database reads. Initial quote snapshots remain substantial; the existing revision/delta mechanism avoids repeatedly sending them unchanged.

Owner/league analytics can still load substantial history when explicitly opened, through pages. Moving those analytics entirely to dedicated server aggregates is a possible later optimization. This delivery does not claim a sustained peak-load or storage/IO plateau test.
